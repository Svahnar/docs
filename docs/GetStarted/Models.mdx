## 🔍 Model Details

Compare every model before choosing one. Credits are charged per run (see [Core Concepts](#-core-concepts)).

**Specifications**

- **Description**: a short summary of what the model is best at.
- **Credits / run**: credits deducted each time an agent using this model runs.
- **Context**: the maximum number of tokens (input plus output) the model can hold in a single run.
- **Max output**: the maximum number of tokens the model can generate in a single response.
- **Parameters**: the model size, where published.
- **Input / Output**: the modalities the model accepts and produces. `text, image` models can read images you attach.
- **Knowledge cutoff**: the date after which the model has no training data.
- **Released**: when the model was launched.
- **Subscription required**: whether a paid plan is needed to use the model.
- **Model card**: the provider's official documentation for the model.

**Capabilities**

- **Reasoning**: the model thinks through a problem step by step before answering, which suits complex or multi-step tasks.
- **Tool calling**: the model can call tools and MCP servers.
- **Structured output**: the model reliably returns data in a requested schema.
- **File / Image / Video / Audio upload**: the kinds of attachments the model can process.
- **Open weights**: the model weights are publicly available.

A dash (—) means the field is not supported or not published for that model.

## 🧭 Choosing a Model

| If you need... | Consider |
|---|---|
| The lowest cost for simple, high-volume steps (routing, classification, short replies) | `gpt-oss-20b` (0.5 credits), or any 1-credit model such as `gpt-5-nano`, `gpt-4o-mini`, `qwen3-32b` or `llama3-1-8b-instruct` |
| A balance of quality and cost | `gpt-5.4-mini`, `gpt-5-mini`, `gpt-4.1-mini` or `llama3-3-70b-instruct` |
| The strongest reasoning for complex agents | `gpt-5.6-terra`, `gpt-5.4`, `gpt-5.2` or `deepseek.r1-v1:0` |
| Very long documents | `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.4` and `gpt-4.1` (about 1M tokens of context) |
| Image input | Models listing `image` under Input, such as the GPT-5 family, `qwen3-vl-235b-a22b` and `llama4-maverick-17b-instruct` |
| Code generation | `qwen3-coder-next`, `qwen3-coder-30b-a3b` or the GPT-5 family |
| Open-weight models | `gpt-oss-120b`, `gpt-oss-20b`, `qwen3-32b`, `deepseek.v3.2` and the Llama models |

:::tip Mix models in one network
Each agent in a network has its own `LLM_config`. Use a low-credit model for simple agents and a stronger one only for the agent that needs it, to keep the total run cost down.
:::

## 📚 Practical Recipes

### Setting the Model in Config

To use a specific model, copy the **Model Name** from the table above and paste it into the `model` parameter of your YAML configuration.

> **Use Case:** Configuring an agent to use a cost-effective model for simple tasks.

```yaml showLineNumbers
create_agent_network:
  agent-1:
    agent_name: simple_task_agent
    LLM_config:
        params:
          # Paste the Model Name here
          model: gpt-5-nano
    tools: []
    agent_function:
      - Reply to the user's greeting.
```

## 💡 Core Concepts

Before selecting a model, it is important to understand how SVAHNAR calculates usage.

### 1. What is a "Run"?
In a multi-agent network, pricing is calculated based on **Runs**. 
A **Run** occurs whenever an agent is triggered to perform a task or participate in a conversation.

### 2. How are credits consumed?
Credits are deducted strictly on a **pay-per-run** basis.
* If an agent uses **gpt-5-nano**, 1 credit is deducted for that turn.
* If an agent uses **gpt-5.4**, 16 credits are deducted for that turn.

:::info
In a complex workflow where multiple agents interact, the total cost is the sum of the credits required for each agent's individual participation.
:::

### 3. Worked example

A network has a supervisor on `gpt-5.4-mini` (5 credits) and two worker agents on `gpt-5-nano` (1 credit each). A single request in which the supervisor and both workers each participate once consumes:

`5 + 1 + 1 = 7 credits`

Credit costs can be fractional (for example `gpt-oss-20b` is 0.5 credits and `gpt-5.4-nano` is 1.5). The credits used by each agent in a request are reported in the `usage` section of the [Run Agent](../Agents/run_agent.mdx) response, together with the total.
